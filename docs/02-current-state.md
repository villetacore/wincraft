# Текущее состояние WinCraft 0.3

Срез исходников от 14.10.2026. При последнем анализе cargo test --locked на Windows-хосте завершился успешно: два PE-теста, ноль тестов init. Linux-ветка init исключена условной компиляцией. Сборка ОС и VM не запускались; наличие реализации и тестового скрипта не означает прохождения release gate. Рабочая директория — Git-репозиторий с незакоммиченными изменениями.

## 1. Что присутствует в коде

| Область | Реализация | Ограничение |
| --- | --- | --- |
| Ядро и база | Linux linux-lts, Alpine, musl | Собственного ядра в основной системе нет |
| Сборка | Свежий chroot по умолчанию, lock сборки, SHA-256 minirootfs, Cargo.lock | APK и toolchain полностью не закреплены |
| Live ISO | GRUB UEFI/BIOS → early-init → squashfs + RAM overlay → switch_root | Требуется повторная приёмка; установщика нет |
| Developer boot | Прямая загрузка kernel/initrd в QEMU | Не заменяет проверку ISO |
| PID 1 | Rust: mounts, устройства, reap, ограничение быстрых падений сессии, shutdown | Не все пути ошибок обработаны |
| Сессия | Desktop и Wine как UID 1000; Xorg остаётся root с cookie-авторизацией | Нет полноценного менеджера входа; X11 не изолирует приложения одного пользователя |
| Debug/release | Serial root shell только в debug; developer mode допускает debug | Требуется регрессионная проверка обычной загрузки |
| Desktop | Rust + egui: меню, файлы, редактор, процессы, настройки | Внешними окнами управляют Xorg/Openbox |
| EXE | compat.rs: предварительная PE-классификация и Wine | Не собственный PE loader; x86/x64 требуют отдельных runtime-тестов |
| Wine prefix | Один $HOME/.wine, маркер готовности | Нет per-app profiles, versioned runtimes и надёжного error state |
| Данные | Диск WINCRAFT_DATA, bind /home и /apps | Без диска данные в RAM; ошибки bind игнорируются |
| Тесты | Два host unit test; QEMU developer и ISO smoke scripts | ISO runner делает debug/release boots, не 10 cold boots; x86 информационный |
| Графика и сеть | Software rendering; QEMU с -nic none | Производительность GPU и сетевая работа не доказаны |

## 2. Найденные проблемы

| Проблема по исходникам | Последствие | Задача |
| --- | --- | --- |
| os/wincraft-user-session: READY создаётся после wineboot без проверки успеха; system.reg принимается за готовность | Неполная инициализация выглядит успешной | FIX-01 |
| src/compat.rs: неограниченное ожидание маркера; GUI сообщает Started после spawn ожидателя | Запуск зависает без понятного результата | FIX-01 |
| src/init.rs: результаты bind-mount не проверяются | При сообщении об успешном диске файлы могут остаться в RAM | FIX-02 |
| src/init.rs: ошибка spawn сессии возвращает None без retry | Desktop не запускается и не восстанавливается | FIX-03 |
| src/main.rs: редактор использует прямой fs::write | Ошибка записи или сбой могут повредить прежний документ | FIX-04 |
| scripts/build-os.sh: APK из изменяемого репозитория | Список пакетов не гарантирует повторение сборки | BUILD-02 |

Маркер готовности не заменяет состояние runtime. Отдельный Wine prefix не является sandbox. В просмотренном session script нет переноса повреждённого prefix в .wine.broken-*; считать это реализованным нельзя.

## 3. Следующий результат

Сохранить Linux/Alpine baseline, developer boot, live ISO, непривилегированную сессию и demo fixtures. Не переписывать загрузку заново и не менять одновременно базу, UI и launcher.

Сначала устранить FIX-01…04 и подтвердить в одноразовых VM сохранение документов после reboot, отказ диска данных, ошибку Wine и восстановление сессии. Затем выбрать 5–10 реальных приложений (fixtures учитывать отдельно), построить менеджер их жизненного цикла и сравнить Alpine с одной glibc-базой на одинаковых сценариях.

Сеть, звук и браузер проверяются в VM до установщика. Далее — установка, обновления с восстановлением, ограниченная аппаратная матрица. См. [дорожную карту](06-roadmap.md) и [backlog](09-backlog.md).
