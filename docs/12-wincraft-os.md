# WinCraft OS: собственный дистрибутив с поведением Windows

Дата: 14.10.2026. Статус: принятое направление владельца проекта; заменяет базу Alpine из 0.2/0.3.
Документ описывает целевую архитектуру и порядок перехода. Что уже реализовано — см. раздел 9.

## 1. Цель

Настольная ОС, которая **для пользователя работает как Windows** (диски, «Этот компьютер»,
Program Files, панель задач, Пуск, Проводник, Диспетчер задач, запуск `.exe` двойным щелчком),
а внутри устроена как открытая Unix-система:

- **Ядро** — ванильный Linux LTS с kernel.org, собственная конфигурация (`distro/board/qemu-x86_64/linux.fragment`).
- **Без дистрибутива-основы.** Всё пространство пользователя собирается из upstream-исходников
  собственной сборочной системой (`distro/`, Buildroot как фреймворк сборки: он компилирует
  toolchain, glibc, Wayland/labwc, Mesa, Wine и др. по нашей конфигурации; пакетного менеджера Buildroot в ОС нет).
- **Windows-программы** — Wine 11 (WoW64: x64 и x86) как подсистема Win32; со временем
  отдельные части заменяются собственными компонентами.
- **Собственные компоненты** — Rust: загрузка, PID 1, сеанс, оболочка, системные приложения.
- **Linux-программы** — штатные бинарники собираются той же системой и запускаются из оболочки.
- **Целевая платформа сейчас — только QEMU x86-64.** Оболочка не запускается на хосте
  (предпросмотр на Windows удалён, ADR-016).

Windows-поведение копируется там, где оно удобно. Где у Windows есть известные неудобства,
делаем лучше и фиксируем решение (раздел 6).

## 2. Идеи ReactOS

ReactOS — образец *архитектуры* Windows-совместимой ОС. Мы перенимаем идеи, а не код
(ReactOS — GPL, собственный код WinCraft — MIT; любые заимствования требуют проверки
совместимости лицензий и сохранения авторства):

| ReactOS / Windows | WinCraft | Реализация |
| --- | --- | --- |
| freeldr / bootmgr | GRUB → `wincraft-boot` | загрузка ISO, поиск носителя, squashfs + overlay, switch_root |
| ntoskrnl | Linux | ядро не пишем |
| smss.exe | `wincraft-init` (PID 1) | монтирование, подсистемы, службы, перезапуск, выключение |
| services.exe | `wincraft-init` (служебный менеджер, позже отдельный SCM) | |
| csrss / win32k | labwc (Wayland, wlroots) + XWayland + Wine (`winex11`) | графическая подсистема (ADR-018) |
| winlogon.exe | `winlogon` | seatd, композитор от имени пользователя, сеанс, блокировка/выход |
| userinit.exe | часть `winlogon` | подготовка профиля и запуск оболочки |
| explorer.exe | `explorer` | рабочий стол, панель задач, Пуск, окна Проводника |
| ntdll/kernel32/user32 | Wine | Win32 API |
| notepad, taskmgr, regedit | `notepad`, `taskmgr`, regedit Wine | системные приложения |
| Реестр | реестр Wine (`system.reg`/`user.reg`) | позже — собственный сервис |
| Shell namespace | `wc-paths` | C:, «Этот компьютер», известные папки |

Порядок старта повторяет NT: `boot → smss(init) → winlogon → userinit → explorer`.

## 3. Структура репозитория

```text
crates/            библиотеки без привилегий, тестируются на хосте (cargo test)
  wc-formats       классификация исполняемых файлов: PE x86/x64, DOS MZ, ELF, скрипты
  wc-paths         пространство имён Windows: диски, известные папки, C:\ <-> unix
  wc-launch        ShellExecute/CreateProcess: .exe -> Wine, ELF -> native, .txt -> notepad
  wc-ui            дизайн-система: тема, цвета, иконки (векторные), общие виджеты
  wc-wayland       Wayland-клиент оболочки: egui на layer-shell (рабочий стол, панель задач),
                   список окон (wlr-foreign-toplevel): активация, сворачивание, закрытие
system/            системные процессы гостя (только Linux)
  wincraft-boot    стадия initramfs: носитель, squashfs, overlay, switch_root (статический)
  wincraft-init    PID 1 (smss + services)
  winlogon         seatd, композитор labwc, сеанс пользователя, выход
apps/              пользовательские программы гостя (только Linux)
  explorer         оболочка
  notepad          Блокнот
  taskmgr          Диспетчер задач
distro/            определение дистрибутива (Buildroot BR2_EXTERNAL)
  configs/         defconfig сборки
  board/qemu-x86_64/  конфиг ядра, overlay rootfs, post-build/post-image, grub.cfg
  package/         собственные пакеты: wincraft (Rust workspace), wincraft-wine (WoW64), labwc
build/             сборочная инфраструктура: изолированный builder, сборка, ISO
tests/             fixtures (Win32 demo), сценарии QEMU
scripts/           запуск и приёмка на Windows-хосте (run-iso, smoke-iso)
docs/              архитектура, решения, планы
```

Правила: чистая логика — в `crates/` с unit-тестами; привилегированный код — только в `system/`;
приложения не ходят в `/run/wincraft/control` иначе как через типизированный API; новый
внешний компонент оформляется пакетом в `distro/package` с версией, хешем и лицензией.

## 4. Пространство имён как в Windows

Под капотом — FHS (нужен Linux-программам), пользователю показывается Windows-модель
(`wc-paths`):

| Пользователь видит | Реально |
| --- | --- |
| Этот компьютер | виртуальная папка: известные папки + диски |
| Локальный диск (C:) | `$WINEPREFIX/drive_c` (тот же C:, что видят Windows-программы) |
| C:\users\user\Documents | `/home/user/Documents` (Wine связывает известные папки с $HOME) |
| C:\Program Files | `drive_c/Program Files` — установленные Windows-программы |
| Приложения (D:) | `/apps` — переносимые программы с диска данных |
| Система WinCraft (Z:) | `/` — для опытных пользователей, как в Wine |

Сравнение путей без учёта регистра, как в Windows. Адресная строка Проводника принимает
`C:\...`, `%USERPROFILE%`, `shell:Documents`-подобные имена и unix-пути.

## 5. Сеанс и окна

Одно окно — один процесс: рабочий стол (хост оболочки и IPC), панель задач (перезапускается хостом), меню Пуск, каждое окно Проводника и диалоги — отдельные процессы `explorer --<режим>`. Это изоляция сбоев, как у отдельных процессов оболочки Windows 11; многооконный режим egui в одном процессе оказался ненадёжным для ввода.

Графика — Wayland (ADR-018). Xorg в системе нет.

- `winlogon` (root) запускает seatd — он один имеет права на DRM и устройства ввода — и затем
  композитор **labwc** от имени пользователя (UID 1000). Команда старта labwc
  `winlogon --report-session` сообщает имена сокетов (`WAYLAND_DISPLAY`, `DISPLAY` для
  XWayland); после этого запускаются подготовка Wine prefix и оболочка. Скриптов-обёрток нет.
- `explorer` — обычный Wayland-клиент: рабочий стол — layer-shell поверхность фонового слоя
  на весь экран, панель задач — верхний слой у нижнего края с резервированием 48 px (развёрнутые
  окна останавливаются над ней). «Пуск», «Выполнить», сообщения — обычные окна; их место задают
  правила `windowRules` в `/etc/xdg/labwc/rc.xml`. Окна Проводника — обычные окна с рамкой labwc.
- Панель задач строится по wlr-foreign-toplevel-management, поэтому в ней видны и Windows-программы
  (они работают через XWayland, `app_id` = WM_CLASS, например `win32-demo.exe`).
- Оконный менеджер — сам labwc с собственной темой WinCraft (заголовок как в Windows: значок и
  заголовок слева, свернуть/развернуть/закрыть справа, Win+←/→ — Snap, Alt+Tab).
  Собственный композитор на Rust — следующий этап: анимации, Alt+Tab с превью, Snap Layouts.

## 6. Где делаем лучше Windows

| Неудобство Windows | Решение WinCraft |
| --- | --- |
| Обновление перезагружает систему без спроса | Атомарные A/B-обновления, применяются при следующей загрузке, откат |
| Скрытые расширения файлов | Расширения видны по умолчанию |
| Реклама/телеметрия в Пуске | Нет; Пуск — только программы и документы |
| Учётная запись Microsoft | Только локальные учётные записи |
| Повреждённая система после сбоя питания | Read-only системный образ; повреждённый Wine prefix переносится в `.wine.broken-*` |
| Права администратора для всего подряд | Программы — от пользователя; системные действия — через узкие привилегированные службы |

## 7. Дизайн

Среднее между Windows 10/11 и ReactOS: ясная структура и подписи ReactOS/Win10 (кнопки панели
задач со значком и текстом, классический Проводник с деревом), визуальный язык Win11
(скругления 4–8 px, акцент `#0067C0`, светлая тема по умолчанию, тёмная в Настройках,
полоса-индикатор активного окна). Собственный логотип (не логотип Microsoft), собственные
векторные иконки в `wc-ui`, процедурные обои. Шрифт — DejaVu Sans до выбора лицензируемой замены.

## 8. Сборка

```text
build/builder.sh setup        изолированный Ubuntu-base chroot с инструментами (один раз)
build/build.sh                Buildroot: toolchain -> ядро -> Mesa/Wayland/labwc/Wine -> Rust -> rootfs
                              -> squashfs + initramfs(wincraft-boot) -> GRUB ISO (UEFI+BIOS)
dist/wincraft-os.iso          результат
```

Первая сборка компилирует всё из исходников (часы); повторные — только изменённое.
Версии закреплены Buildroot-хешами пакетов и нашими `.hash`-файлами.
